# WeKnora 课题四：知识掌握管理与引导式学习

## 四个切入点联合优化（2026-09-12，原型验收完成）

当前组件模型为 `kc-evidence-separated-v2`：阅读自动更新进度，但不提高表现指数；自评熟悉用于减少重复学习；不同题族的独立检查提供表现证据；真实回忆继续交给 FSRS。星图、导航、详情和助手区分“已阅读”“自评熟悉”“检查支持”。无独立检查时不展示能力数值。旧事件保留，通过重放修正状态，无须重建知识库。

四项研究、假设、基线与验收范围见 [联合建模分析](docs/research/learning-framework/题目分析.md)，两份公开数据的预测对照、负面结果及弱信号修复见 [实验与实施记录](docs/research/learning-framework/实验结果与实施记录.md)。组件长期记忆候选关联与依赖预算规划已实现，100 个小图的独立穷举对照、规模限制及真实页面记录见 [关联与路径验证](docs/research/learning-framework/关联与路径验证记录.md)。关联不产生掌握证据，规划效用不等于真实学习收益。通用材料候选已完成三主题验证，最终统一审计见 [原型设计与验收](docs/research/learning-framework/原型设计与验收.md)。未配置学习单元的库也已统一为阅读、自评与独立检查分开的页面模型 `page-evidence-separated-v3`，普通阅读顺序使用 `path-plan-v8-evidence`。实际学习收益和自动材料语义质量仍不能据此保证。**以下内容保留为历史实施记录，涉及阅读累加、自评似然比和“估计熟悉”的旧组件参数已由本节与新实验文档替代。**

通用候选生成与无题学习现已接入：按目标及条件整理完整材料，候选不自动发布，模型关系不作为硬先修。三类主题的实际生成得到 11 个候选，作者核对发现至少 5 个需要修订；原输出、修订与生产算法闭环记录见 [材料候选与跨主题验证](docs/research/learning-framework/材料候选与跨主题验证记录.md)。这一结果支持保留来源复核，不支持全自动高质量制课的宣传。新增 `/components/draft` 与本地命令入口，不新增运行依赖或数据库表。

本轮原型验收已完成，最终前端 478 项测试、完整类型检查和构建通过，学习服务／模型、handler 及类型回归通过。真实页面验证了无需确认的阅读推进、纠偏后的自动继续、FSRS 复习保存与刷新恢复、助手与导航一致；代理验收操作单独视为工程数据，创建的复习已暂停。公共数据实验已重跑并得到一致结果；少量本地校准数据的采集方式见 [数据集使用方案](docs/research/learning-model/数据集使用方案.md)。

## 原型定位（2026-09-11 校正）

课题交付的中心是关联、度量、引导、呈现的建模假设、原型算法和可检验闭环。企业知识管理库是应用情境；本轮以设计合理性和最小可运行验证为验收重点。前端是用户理解状态、表达学习动作以及观察算法结果的实验界面，信息组织与反馈是否清楚会直接影响数据质量。

默认闭环为：查看模型建议 → 阅读 → 自动更新估计与下一步。判断不符时，可反馈已经熟悉或仍有困难；没有题库也能学习，不要求逐页确认。间隔复习、少量测验与任务检查作为可选实验；完整题库、复杂审核运营、长期员工试验和生产多实例负载属于后续扩展，不作为课题原型完成的前置条件。基本身份隔离、画像权利和保存一致性仍需可靠。

设计与轻量验证范围见 [交付重心与界面收敛](docs/reviews/课题四_交付重心与界面收敛_2026-09-10.md) 开头的最新定位。已有工程能力保留使用，后续新增能力须说明它检验哪个假设、修正哪种可观察错误，以及现有规则为何不足。

## 当前原型行为

学习页覆盖全部 entity/concept 节点，模型主视图显示未接触、初步接触、阅读推进、估计熟悉、建议巩固，验证通过另行保留。可见阅读 5 秒记录初步机会，持续阅读阈值按内容长度估计为 8–180 秒。阅读会自动更新估计并降低立即重复阅读的优先级；纠偏有上限、重复声明不累加。数值是原型的熟悉度指数，参数范围不是统计置信区间，也不是已验证的掌握概率。

此前用户反馈版本的验收保留在 [9 月 11 日深化优化记录](docs/reviews/课题四_深化优化与验证_2026-09-11.md) 和 [9 月 10 日学习闭环](docs/reviews/课题四_学习引导与掌握闭环优化_2026-09-10.md)；本轮以模型验证记录为准。右栏包含模型状态分布、可筛选清单、时间预算、可执行的下一步和模块覆盖条。点击模块可集中学习，点击节点在学习页内阅读。画像查看、导出、删除入口保留。

## 已实现的链路

- 概念契约 v1：闭卷、当前内容版本、两独立题族。草稿、旧数据缺元信息、同题族反馈重试、辅助条件不符和“不确定”不增加独立验证覆盖。固定规则版本不接受未实现的自定义参数。
- 应用任务：结构化字段选择，服务端核对全部关键检查；JSON 不含答案键和可能泄漏答案的检查说明。任务是限定情境的选择验证，不自动代表编码/部署能力。
- 内容审核：Web 用户经知识库写权限审核；冻结来源、目标/题目/任务/评分器版本。内容变化或语义更正使旧证据保留为历史、当前待复核；旧题不能自动贴上新版本。
- 学习路径（`path-plan-v7-model`）：依据预计阅读收益与时间成本排序，再考虑有上限的工作相关性与后继解锁价值；模块范围、临时排除、已审核先修与预算仍是约束。普通学习不默认完成全部题库契约。最多一次可选自测，由预计信息增益、题目可用性、预算和近 24 小时作答情况决定；有到期回忆或待巩固行动时不再叠加自动自测。
- 个性化与探索：用户可选择参考长期记忆主题和常用文档，关联不制造掌握证据。保留收益排序的前四候选，再给未接触内容一个可重放的探索位置，仍遵守预算和依赖。已经熟悉的声明调整模型后验，正常阅读也会自动改变后续顺序。
- 个人间隔复习（`fsrs6-go4-default-v1`）：需要长期记牢的内容可主动加入。使用正式 go-fsrs v4.0.0 的 FSRS-6 实现；“忘记、费力、正常、轻松”只来自真实回忆核对，后三项都代表回忆成功。目标保持率 0.9，保留短时学习步骤，间隔最多 365 天。旧 SM-2 记录保留原时间安排，下一次复习操作后从真实历史重放切换。普通阅读与自认熟悉不伪造回忆成功。
- 同一轮学习：右栏与知识助手共用实际应用后的模块、预算、深度和排除项。设置草稿不改变已应用计划；失败或加载时不使用旧计划冒充当前推荐。助手页面上下文也由各知识库页面实例持有，阻止后台阅读器或旧账号内容覆盖当前界面。
- 知识助手：修复聊天组件运行时崩溃；会话和上下文按用户、租户、知识库隔离，学习状态变化后刷新；隐藏界面上下文协议文本并消除初始历史与发送消息竞态产生的重复气泡。
- 数据边界：新任务写入使用用户事务和删除代际栅栏；回滚、停止采集、删除后的旧写入以及跨租户内容 ID 冲突均有测试。
- 独立评估：服务端冻结无标签状态，外部脚本单独呈现保留挑战、确定性评分、汇总。评估器校验时间、身份、资格、阶段、题族、来源与完整分母；按用户处理置信区间。

学习模块、目标、深度、时长和记忆参考偏好保存到服务端，按用户、租户和知识库隔离，重新打开时恢复。多页面修改有修订冲突检测；保存失败时本轮计划仍可使用。临时跳过和“已有基础，直接验证”仅影响本轮。偏好纳入画像导出、删除及知识库清理。模型与决策阈值是可检验的原型假设，尚未经过企业人群的个体参数校准。

## 启动和迁移

学习层需 `LEARNING_ENABLE=true`。本机课题四使用 **Hybrid 环境 A：Docker Desktop 开发基础设施 + 本地后端 18081 + Vite 5173**。WSL 的 80/18080 环境使用另一套数据库。源码改变后必须重新构建后端。在 Docker Desktop Linux 引擎已就绪后，在 **PowerShell 7** 中执行：

```powershell
pwsh -NoProfile -File scripts/check-learning-infrastructure.ps1 -StartContainers
pwsh -NoProfile -File scripts/restart-learning-backend.ps1
# 以下仍在仓库根目录执行，用独立终端保持前端运行：
$env:VITE_DEV_PROXY_TARGET='http://127.0.0.1:18081'
npm --prefix frontend run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

基础设施脚本固定检查 `desktop-linux`，确认四个开发容器及端口就绪；Docker 请求有超时，失败会停止启动链。`-StartContainers` 只启动开发基础设施，不拉取镜像、不重建已有容器。后端脚本先检查基础设施，再构建独立的带时间戳二进制，校验并替换本工作区的 18081 服务，执行健康检查。检查或构建失败不会停止现有服务；`-SkipBuild` 使用最近构建产物。配置从本地 `.env` / `.env.local` 读取，日志位于 `.local-data/logs`。本地 `hls/start-dev.sh` 已调用上述脚本；`hls` 属于本机忽略目录，其他机器以 `scripts` 中的脚本为准。

## 评估

原型先使用可控知识切片与固定行为序列，检查关联范围、状态更新、先修/预算约束以及操作后推荐变化。用同一组情境比较目录顺序、仅个人状态排序与加入关联信息的结果；允许的下一步集合应先于运行确定，避免把算法自身输出作为正确答案。少量实际操作用于检查用户是否理解状态和按钮含义。由此可以评价设计合理性，不能直接推出真实学习效率收益。

需要进一步检验状态与独立作答的关系时，可选用 [独立评估执行说明](docs/evaluation/objective-learning/README.md) 中的 `capture → present → grade → assemble → assess`。服务端冻结端点为 `GET /api/v1/learning/kb/:kb_id/assessment-freeze`。外部评分不会更新日常画像，这套扩展流程不要求每位学习用户执行。

```powershell
go run ./cmd/learning-bench -mode assess -assess-input docs/evaluation/objective-learning/engineering-fixture.json -assess-out <新的结果文件.json>
```

演示输入和报告是 `engineering_fixture`。`simulate/replay/verify/walk/optimize` 分别服务于工程规则、行为预测或旧模型研究，不能当作真实用户学习效果。混合来源必须分开评估；数据标签、哈希和截图本身不能认证“真人”。

如需进一步声称真实学习效率、长期保持或生产规模效果，应另行收集相应证据；这些结论不属于当前原型已证明的范围，也不作为本课题必须建设的完整产品流程。选择小规模试用时如实保留任务、耗时、理解偏差和失败，避免以点击更多、界面更丰富替代设计有效。
