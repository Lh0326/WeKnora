# WeKnora 课题四：知识掌握管理与引导式学习

## 原型定位（2026-09-11 校正）

课题交付的中心是关联、度量、引导、呈现的建模假设、原型算法和可检验闭环。企业知识管理库是应用情境；本轮以设计合理性和最小可运行验证为验收重点。前端是用户理解状态、表达学习动作以及观察算法结果的实验界面，信息组织与反馈是否清楚会直接影响数据质量。

默认闭环为：看懂知识分布与建议 → 阅读或询问 → 确认已会／需要再学／换一个 → 更新状态与下一步。简单内容允许直接确认已会。间隔复习、少量测验与任务检查作为可选实验；完整题库、复杂审核运营、长期员工试验和生产多实例负载属于后续扩展，不作为课题原型完成的前置条件。基本身份隔离、画像权利和保存一致性仍需可靠。

设计与轻量验证范围见 [交付重心与界面收敛](docs/reviews/课题四_交付重心与界面收敛_2026-09-10.md) 开头的最新定位。已有工程能力保留使用，后续新增能力须说明它检验哪个假设、修正哪种可观察错误，以及现有规则为何不足。

## 当前原型行为

学习页覆盖知识库全部 entity/concept 节点，分别显示未开始、学习中、自认已会、验证通过、待巩固。阅读 5 秒自动记录，60 秒在当前页面反馈深入阅读；简单内容可以立即确认学会并点亮，随后优先推荐其他内容。主动标记、阅读接触和客观验证分别记录，不把阅读次数换算成未经校准的掌握概率。

当前实现与验收见 [9 月 11 日深化优化记录](docs/reviews/课题四_深化优化与验证_2026-09-11.md) 和 [9 月 10 日学习闭环](docs/reviews/课题四_学习引导与掌握闭环优化_2026-09-10.md)。右栏包含已会覆盖、可筛选状态清单、时间预算、可执行的下一步和模块覆盖条。覆盖明确区分自认已会与验证通过；点击模块可集中学习，点击节点在学习页内阅读。画像查看、导出、删除入口保留。

## 已实现的链路

- 概念契约 v1：闭卷、当前内容版本、两独立题族。草稿、旧数据缺元信息、同题族反馈重试、辅助条件不符和“不确定”不增加独立验证覆盖。固定规则版本不接受未实现的自定义参数。
- 应用任务：结构化字段选择，服务端核对全部关键检查；JSON 不含答案键和可能泄漏答案的检查说明。任务是限定情境的选择验证，不自动代表编码/部署能力。
- 内容审核：Web 用户经知识库写权限审核；冻结来源、目标/题目/任务/评分器版本。内容变化或语义更正使旧证据保留为历史、当前待复核；旧题不能自动贴上新版本。
- 学习路径：模块/目标范围、深度、时间预算、最近阅读与显式待巩固共同生成最多五步路径。只将人工审核的先修关系用作严格依赖；本轮临时跳过可恢复。读过但未确认的内容提供确认理解，有已审核题库时提供验证，缺少题库仍能完成自主学习闭环。
- 个性化顺序（`path-plan-v6`）：用户可选择参考长期记忆主题与常用文档。同用户、租户和知识库的有效关联影响候选顺序；显式待巩固、已会跳过、先修关系与预算约束仍优先。主动加入的到期复习最多占一项、约两分钟，按到期时间选择，并遵守模块与本轮排除。关联不产生掌握证据。
- 个人间隔复习（`sm2-recall-v1`）：简单内容可直接确认已会，需要长期记牢的再主动加入。完成回忆与材料核对后，通过“忘记、费力、正常、轻松”反馈调整间隔；可暂停，提前成功练习不会拉长间隔。回忆反馈只影响自认状态与复习时间，客观验证独立保留。
- 同一轮学习：右栏与知识助手共用实际应用后的模块、预算、深度和排除项。设置草稿不改变已应用计划；失败或加载时不使用旧计划冒充当前推荐。助手页面上下文也由各知识库页面实例持有，阻止后台阅读器或旧账号内容覆盖当前界面。
- 知识助手：修复聊天组件运行时崩溃；会话和上下文按用户、租户、知识库隔离，学习状态变化后刷新；隐藏界面上下文协议文本并消除初始历史与发送消息竞态产生的重复气泡。
- 数据边界：新任务写入使用用户事务和删除代际栅栏；回滚、停止采集、删除后的旧写入以及跨租户内容 ID 冲突均有测试。
- 独立评估：服务端冻结无标签状态，外部脚本单独呈现保留挑战、确定性评分、汇总。评估器校验时间、身份、资格、阶段、题族、来源与完整分母；按用户处理置信区间。

学习模块、目标、深度、时长和记忆参考偏好现在保存到服务端，按用户、租户和知识库隔离，重新打开时恢复。多页面同时修改采用修订标识检测冲突；保存失败时本轮计划仍可使用。临时跳过和“已有基础，直接验证”仅影响本轮。偏好纳入画像导出、删除及知识库清理。规则仍是可解释的导航规则，不是已经校准的个体概率模型。

## 启动和迁移

学习层需 `LEARNING_ENABLE=true`。本机课题四使用 **Hybrid 环境 A：Docker Desktop 开发基础设施 + 本地后端 18081 + Vite 5173**。WSL 的 80/18080 环境使用另一套数据库。源码改变后必须重新构建后端。在 Docker Desktop Linux 引擎已就绪后，在 **PowerShell 7** 中执行：

```powershell
pwsh -NoProfile -File scripts/check-learning-infrastructure.ps1 -StartContainers
pwsh -NoProfile -File scripts/restart-learning-backend.ps1
# 以下仍在仓库根目录执行，用独立终端保持前端运行：
$env:VITE_DEV_PROXY_TARGET='http://127.0.0.1:18081'
npm --prefix frontend run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

基础设施脚本固定检查 `desktop-linux`，确认四个开发容器及端口就绪；Docker 请求有超时，失败会停止启动链。`-StartContainers` 只启动开发基础设施，不拉取镜像、不重建已有容器。后端脚本先检查基础设施，再构建独立的带时间戳二进制，校验并替换本工作区的 18081 服务，执行健康检查。检查或构建失败不会停止现有服务；`-SkipBuild` 使用最近构建产物。配置从本地 `.env` / `.env.local` 读取，日志位于 `.local-data/logs`。本地 `hls/start-dev.sh` 已调用上述脚本；`hls` 属于本机忽略目录，其他机器以 `scripts` 中的脚本为准。

## 内容与人工审核

`cmd/learning-seed` 现在只导入草稿，不接受 `-reviewer`，不制造 Web 用户身份。ID 按租户/知识库生成；重复导入拒绝覆盖已存在目标。候选来源、题族和答案仍需真实内容负责人逐项复核。

```powershell
# DSN 通过 WEKNORA_SEED_DSN 环境变量传入，避免写入命令历史。
go run ./cmd/learning-seed -tenant <租户ID> -kb <知识库ID>
```

原演示包中温度正反问已经合族；目前不能宣称所有概念都有两独立题族。详细内容问题、已修订草稿与人工审核要求见 [内容修订清单](docs/reviews/课题四_内容修订与人工复核清单_2026-09-10.md)。

审核接口仍需认证及知识库写权限：`POST /learning/kb/:kb_id/objectives/:id/review`、`quiz/:id/review`、`tasks/:id/review`。提交 `decision`、`change_kind`、`note`，题目关联还包括 `objective_id`、`family_id`。必须先实际阅读目标、来源、题目/任务和答案，不能批量调用 approve 后倒推“已人工审核”。

## 评估

原型先使用可控知识切片与固定行为序列，检查关联范围、状态更新、先修/预算约束以及操作后推荐变化。用同一组情境比较目录顺序、仅个人状态排序与加入关联信息的结果；允许的下一步集合应先于运行确定，避免把算法自身输出作为正确答案。少量实际操作用于检查用户是否理解状态和按钮含义。由此可以评价设计合理性，不能直接推出真实学习效率收益。

需要进一步检验状态与独立作答的关系时，可选用 [独立评估执行说明](docs/evaluation/objective-learning/README.md) 中的 `capture → present → grade → assemble → assess`。服务端冻结端点为 `GET /api/v1/learning/kb/:kb_id/assessment-freeze`。外部评分不会更新日常画像，这套扩展流程不要求每位学习用户执行。

```powershell
go run ./cmd/learning-bench -mode assess -assess-input docs/evaluation/objective-learning/engineering-fixture.json -assess-out <新的结果文件.json>
```

演示输入和报告是 `engineering_fixture`。`simulate/replay/verify/walk/optimize` 分别服务于工程规则、行为预测或旧模型研究，不能当作真实用户学习效果。混合来源必须分开评估；数据标签、哈希和截图本身不能认证“真人”。

如需进一步声称真实学习效率、长期保持或生产规模效果，应另行收集相应证据；这些结论不属于当前原型已证明的范围，也不作为本课题必须建设的完整产品流程。选择小规模试用时如实保留任务、耗时、理解偏差和失败，避免以点击更多、界面更丰富替代设计有效。
