# 个人学习原型：可复现验证

协议版本：`personal-learning-evaluation-v1`，2026-09-12。

本评估直接调用生产服务使用的投影与规划算法，不另造一个评分模型。用于证明关联边界、证据归属、规划约束和界面状态的一致性；这些结果不能单独证明真人学习效率提高。

## 运行前固定的判断标准

| 切入点 | 客观检查 | 能回答的问题 | 不能据此声称 |
|---|---|---|---|
| 关联 | 同页不同目标隔离、多来源身份、来源版本、候选权重守恒、越界和循环拒绝 | 学习证据是否正确归属，关联是否会虚增 | 自动生成的目标在所有主题上都语义正确 |
| 度量 | 阅读/自评/独立检查分离、题族去重、版本隔离、困难与真实回忆处理 | 是否误把接触或重复答题当作掌握 | 数值已校准为本地用户的真实答对概率 |
| 引导 | 底层组合搜索的小图独立穷举与同效用贪心基线；目标选择、模块范围、连续学习与预算回退的行为回归 | 组合搜索是否遵守约束，以及实际导航是否按声明规则选择目标与先修 | 目标选择最优，或效用增加就是实际学习增益 |
| 呈现 | 前端状态标签、覆盖统计、星图/路径/助手共用状态、错误与空状态测试 | 不同界面是否一致且没有虚假验证表述 | 真人阅读理解、操作效率或满意度已经提高 |

规划比较固定种子 20260912：100 个 8–10 节点图，以及 20/40/100/500 节点规模案例。100 个小图已在开发中看过，因此本次是可复现回归比较，不是从未观察过的新测试集。大图没有穷举最优解，只报告可行性、基线、上界和截断。所有规模结果都保留。

当前学习单元导航策略 `kc-goal-progression-v3` 先选一个推进目标，再在目标及其必要先修内搜索。上述 100 图比较调用底层组合搜索，不能用于证明新增目标选择策略最优。目标选择由独立列出的行为回归覆盖：近期模块连续性、到期回忆、自愿检查不阻断新阅读、范围内回退、失效来源与跨模块先修。`Exact` 和效用上界仅属于已选目标的候选组合。历史评估与后续补验保留各自源码指纹，不将旧全量结果表述为最终树的完整重跑结果；这一补充不改变既有比较的种子、权重或结果。

普通 Wiki 导航策略 `path-plan-v9-focus` 同样由行为回归覆盖，检查模块范围、单一目标选择、连续阅读及空数据边界。材料未提供人工确认的先修关系和可用检查时，它只支持连续阅读建议，没有课程递进或能力达成的验证证据；这些行为回归也不证明真人学习成效。

候选约束也有版本差异：当前对已读目标提供可选检查时，不要求重做其先修动作，但仍验证先修引用存在且来源有效。即使种子与效用未变，这也会改变可行集合，因此两版“优于贪心的图数”不能直接用作方案提升证据。`testdata/component-plan-protocol.md` 保留底层比较的原始约定；其中预算变化属于算法或接口检查，当前用户界面无需选择学习时长。

现有跨主题材料是合成案例，经实现作者复核；它们支持边界测试，不能充当独立专家评审。公开教育数据上的预测实验与当前部署的学习单元模型不同，不纳入此处的直接有效性结论。

运行后不根据单个得分反复调整权重。只修复确定的归属错误、约束违反、状态不一致或执行失败；修复后保留失败记录并重新运行。若改动目标定义、效用或题目，另立协议版本，旧结果不得当作新方案的独立验证。反复按评估结果选方案可能带来选择偏差，参见 [Cawley 与 Talbot，JMLR 2010](https://jmlr.org/papers/v11/cawley10a.html)。

## 一条命令生成证据

需要项目正常的 Go/CGO 环境、Python 3，以及已安装依赖的前端。命令不会启动服务，不读取真实用户数据，也不写入学习画像。

若要包含 PostgreSQL 专项检查，先创建仅供本次测试的空数据库，将其连接串通过 `LEARNING_TEST_POSTGRES_DSN` 环境变量提供；不要使用应用正在运行的数据库。测试会在该测试库内创建随机 schema，结束后清理。未设置此变量时，PostgreSQL 检查会明确列为跳过；报告不标为全部完成，命令返回非零退出码。连接串不写入评估报告。

```text
python scripts/evaluate_learning_prototype.py --out .local-data/evaluation/run-001
```

输出包含源码哈希、完整命令日志、测试清单、规划比较原始结果及 `report.md`。输出目录必须尚不存在，且应放在 `.local-data` 等源码扫描范围之外；失败和跳过都原样保留。运行期间源码变化会将报告标为不可用于该版本结论。测试数量仅说明执行覆盖，不换算成项目分数。

默认检查学习服务、仓储、接口、处理器、路由、数据库迁移、评估/导入工具、评估脚本及前端测试。前端类型检查与构建应在交付候选上另行执行。依赖缺失或运行失败应修复并换一个输出目录重跑，不能删除失败条目后宣称通过。

## 真实学习效果的补充验证

使用 `scripts/learning_assessment.py` 的学习单元独立评估链。先冻结目标版本、材料、分组、学习预算及评分规则，题目不导入日常练习库；后测开始前冻结用户状态，再呈现未暴露的题族，按确定规则评分，结果不写回日常画像。冻结至作答结束不得编辑或重新解析评估材料：主体事务隔离个人事件，但默认数据库隔离级别不提供共享材料的全库原子锁。具体格式和执行步骤见 [独立评估说明](../objective-learning/README.md)。

只有一位参与者时，可以在一个主题上做短前测、固定时长学习、独立后测，并列出原始答题数、分数、帮助和缺失。用 `describe` 输出单人描述性结果，不计算群体显著性，不把多个目标当成多个人。前后题的难度和覆盖不等价时，只并列成绩，不宣称净学习增益；呈现到作答的墙钟间隔也不是纯学习时间。

要比较旧方案与新方案，应使用相同目标内容、同等学习时长与帮助条件，按参与者分组或使用独立且难度可比的主题交叉分配，并控制顺序和已有知识。单人已熟悉材料的连续重复测试有记忆影响，只能探索性报告。没有符合条件的真实学习测量时，应标注“学习效果尚未验证”；已经完成但条件不足的试用仍须保留原始结果和负面反馈，不能推算提升百分比。
