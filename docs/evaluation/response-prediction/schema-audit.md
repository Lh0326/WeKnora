# 公开数据结构核对（指标运行前）

日期：2026-09-12。对应 `evaluation-protocol.json`，该文件在拟合和计算结果之前记录。

- 固定提交的 `as.csv`：83,201,940 字节，SHA256 `f22e3fb7872c1784ce93b0f9ebabbe0cbcac4f896fd8b4a11667b9715d77dbdc`，525,534 行。原始文件只存 `.local-data`。
- CSV 包含非 UTF-8 文本；以 Latin-1 无损解码，学习者/技能数字身份和二元标签仍按 ASCII 解析，不丢弃解码失败的整行。
- `original=1` 是主问题，`0` 是脚手架问题，依预先协议仅使用主问题。
- 技能 ID 非空值均为数字；一个事件可以按多个技能重复成多行。先按 `(user_id, order_id)` 聚合，多个技能的事件整体排除，不选择第一行或复制标签；同一事件相同技能的重复仅保留一次，不同标签视为冲突排除。
- 官方字段说明将 `correct=0` 定义为首次错误**或求助**，因此结果指标针对这一复合观测，而非纯粹的未求助答题能力。`first_action` 的 0/1/2 数字映射未从本次读取的官方页面可靠核实，不凭猜测筛除其中一类；`hint_count` 是整次事件计数，也不用于猜测首次动作。该限制须留在结果中，不拿该数据与本地独立检查等同。
- `order_id` 在官方说明中为按时间顺序的原始日志 ID，可以排序，但不能推算实际时间间隔。
- “答对若干次后不再发题”的数据采集机制带有停止偏差；不同学习者的序列长度不能直接当成学习速度。

字段和使用说明：[ASSISTments 2009–2010 数据说明](https://sites.google.com/site/assistmentsdata/home/2009-2010-assistment-data)。固定数据副本由 [pyBKT 示例仓库](https://github.com/CAHLR/pyBKT-examples) 提供；这里只按已核对的格式使用，不声称它等同于其他文献所有预处理版本。
