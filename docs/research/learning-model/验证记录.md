# 模型验证记录

## 2026-09-11：公开作答数据第一轮

实验是知识追踪的先导实验，不是企业文档学习效率评测。运行方式：

```powershell
python scripts/learning_model_benchmark.py --fetch
python -m unittest discover -s scripts -p test_learning_model_benchmark.py -v
```

依赖为 Python + NumPy；本机使用 Codex 随附 Python 环境。下载只写入 `.local-data/research/learning-model/ct.csv`，无数据库连接和学生原始数据再分发。数据固定到作者仓库提交 `fc592907f41dfa0e71742ed1d24f1f6df08e1ad1`，校验值、运行环境、完整分箱结果见 `public-bkt-results.json`。

### 数据与协议

读取到 16,857 条作答，587 位学生，12 个知识技能；本轮筛选无排除行。按学生标识的固定哈希划分训练 367 人/10,555 条、验证 107 人/2,931 条、测试 113 人/3,371 条。逐次预测先于当前结果更新；不同用户和技能的状态分别维护。

BKT 在训练集枚举 400 组受约束的四参数。测试比较中的固定先验 `[0.2,0.1,0.2,0.1]` 是明确标注的启发式对照。拟合参数 `[0.4,0.15,0.35,0.2]` 属于这个数学作答数据集，不能直接宣称为企业知识阅读的已校准参数。

初拟方案中的 50 条校准前缀不适合本子集：在读取序列长度、尚未得到预测指标时，发现多数用户只有 20–40 条记录，验证集没有 70 条以上用户。因此在首次成功产生结果前，将协议改为前 0/3/5/10 条校准，同一用户第 11 条以后的固定后缀评估，仅纳入至少 20 条记录者。该调整依据可用数据长度，不依据模型输赢。

### 首次测试结果

以下三项均越低越好；所有模型使用同一测试分母。

| 模型 | Log loss | Brier | ECE（10 个等宽箱） |
|---|---:|---:|---:|
| 训练集总体平均正确率 | 0.66996 | 0.23848 | 0.01552 |
| 训练集技能平均正确率（收缩） | **0.62812** | **0.21916** | 0.01798 |
| 手设参数 BKT | 0.66557 | 0.23750 | 0.11844 |
| 训练集拟合 BKT | 0.62888 | 0.21992 | 0.05025 |

不能宣称拟合 BKT 击败了技能均值基线。BKT 的拟合显著影响其预测质量，但仅一个跨技能共用的参数组不足以证明优于更简单的模型。ECE 与预测区分能力不同，低 ECE 也不能单独证明模型有用。

### 少量个人观测的校准

在验证集选择收缩强度后，固定到测试用户；只校准一个 logistic 偏移，不重新拟合全部 BKT 参数。对同一未来后缀的 Log loss：

| 可用于校准的前序作答数 | Log loss |
|---:|---:|
| 0 | 0.602840 |
| 3 | 0.603046 |
| 5 | 0.602666 |
| 10 | 0.600540 |

3 条观测略差，10 条观测有小幅改善。该结果支持“保守收缩、检查校准是否有用”的实施方向，但还不能证明用户主观反馈具有相同效果：这里的标签来自真实作答，不是“我已学会”的声明。

### 对后续实现的约束

- 保留简单且强的基线，不能将 BKT/FSRS 的名气当作项目效果证据。
- 理解模型需考虑技能/内容差异；进一步候选只允许在训练和验证数据上选择。当前测试集已用于先导分析，后续调研不得把重复使用它的结果包装成一次性盲测。
- 学习机会的阅读折扣、自评似然及新节点先验仍是待校准参数，主界面必须承认估计依据不足。
- FSRS 接入以正式上游实现和真实回忆事件为依据，不能让浏览事件冒充回忆成功。
- 尚需完成模型与线上事件、推荐器、星图、右栏和助手的一致接入及真实页面验收。

## 2026-09-11：模型接入、决策对照与真实页面

### 实现与已修正的问题

- `bkt-reading-envelope-v2` 同时用于节点画像、星图、模块统计和路径。阅读为无标签的预测转移，独立答题为贝叶斯观测；自评采用有界似然修正。引用与追问不作为答题标签。
- 修正阅读合并的时间顺序：后来发生的深入阅读只补足当日剂量，不删除之前的初步阅读，否则会改写夹在中间的答题预测。
- 修正“答错却上涨”：服务适配不再假定用户读过了解析；没有观察到学习机会时，只更新答题后验。
- 普通路径不再逐页要求确认，也不因存在题库就默认完成全部验证契约。信息增益选出的可选检查受题目资格、先修、24 小时间隔和预算约束。
- 困难反馈后可继续阅读，新的持续阅读解除行动上的待巩固提示。同日已计满的阅读不额外增加学习剂量；阅读器会在当前页重新计时，不需要关闭重开或再次声明。
- 正式 FSRS-6 替换新复习安排；修正成功回忆后立刻又推荐同一页普通阅读的问题。旧 SM-2 事实保留，迁移不批量改写历史。
- `assessment-freeze` 增加带模型版本、内容哈希与时间的节点估计，可先保存快照、再做独立检查。它为后续本地数据集提供入口，不将测试工具动作冒充真实学习结果。

### 六个预定义决策情境

输入及允许的下一步集合固定在 [decision-protocol.json](decision-protocol.json)，结果在 [decision-results.json](decision-results.json)。对比目录顺序、上一版用户状态规则和新模型路径。

| 情境 | 目录顺序 | 用户状态规则 | 模型路径 |
|---|---|---|---|
| 无历史冷启动 | 符合 | 符合 | 符合 |
| 阅读 A 后继续 B | 重复 A | 要求确认 A | 自动推荐 B |
| A 已熟悉的纠偏 | 重复 A | 推荐 B | 推荐 B |
| B 存在困难 | 仍推荐 A | 回看 B | 回看 B |
| 反馈 A 困难后又阅读 A | 重复 A | 继续回看 A | 自动推荐 B |
| 只有问答引用 | 符合 | 要求确认 A | 保留阅读选择 |

六项行为要求，目录顺序符合 2 项，用户状态规则符合 3 项，模型路径符合 6 项。这是依据产品要求构造的工程情境，不是真实用户学习成绩，不用于宣称提升百分之多少的学习效率。先修、预算、排除、信息增益、探索稳定性另有测试，不能由这六个小情境代替。

复现方式：在本机 Go/CGO 环境中设置 `LEARNING_MODEL_REPORT` 为输出 JSON 的绝对路径，运行 `go test -p=1 ./internal/application/service/learning -run TestModelDecisionProtocol -count=1 -v`。

### 参数敏感性与决策消融

[parameter-sensitivity.json](parameter-sensitivity.json) 由实际 Go 估计器生成，包含阅读折扣 0.1/0.25/0.5、完整阅读机会 1/5/10 个不同日期、自评似然比 1/2/4/8 的 36 组结果。没有生成答题标签，以下指数变化不等于准确率或学习收益。

| 条件 | 九组假设的平均熟悉度指数 |
|---|---:|
| 一次完整阅读，折扣 0.1，无纠偏 | 约 0.29 |
| 一次完整阅读，折扣 0.25，无纠偏 | 约 0.33 |
| 一次完整阅读，折扣 0.5，无纠偏 | 约 0.39 |
| 默认阅读折扣、10 个不同日期的完整阅读，无纠偏 | 约 0.46 |
| 默认折扣、一次完整阅读，再以似然比 2 自评熟悉 | 约 0.49 |
| 同上，似然比 4 | 约 0.65 |
| 同上，当前原型似然比 8 | 约 0.78 |

自评的影响显著高于一次弱阅读机会，这是当前需要校准的关键假设，不能因正常路径已自动推进就声称反馈权重已最优。参数范围保持为敏感性范围；主观纠偏不生成客观验证。

`TestModelUtilityAblations` 检查同一两节点切片：移除阅读估计时回到目录顺序；加入阅读估计或熟悉纠偏后转向未学节点；相近收益时相关性可以改变顺序；即使兴趣计数任意增大，也不能压过明显更高的学习收益。它与六情境对照一起检验模型组件是否真正影响决策，不是学习效果实验。

复现敏感性报告：在项目根目录设置 `LEARNING_SENSITIVITY_REPORT` 为输出 JSON 的绝对路径，运行 `go test -p=1 ./internal/application/service/learning -run 'TestReadingAndFeedbackSensitivity|TestModelUtilityAblations' -count=1`。未设置变量时仅执行检查，不写报告。
