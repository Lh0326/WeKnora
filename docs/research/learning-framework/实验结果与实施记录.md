## 1. 预测比较：历史信息有用，统一套用模型仍不可靠

使用 pyBKT 示例仓库固定提交的数据副本。CT 为 16,857 条响应，AS 经主问题、单技能事件、重复记录处理后为 214,425 条。按用户确定性划分训练/验证/测试；测试分别有 123 人/3,545 条和 819 人/40,072 条。原始数据不进入仓库或本地用户数据库。

| 模型 | CT 测试 Log loss ↓ | AS 测试 Log loss ↓ |
|---|---:|---:|
| 训练全局均值 | 0.65518 | 0.64654 |
| 平滑技能均值 | 0.61202 | 0.62454 |
| 手设 BKT | 0.66798 | 0.63725 |
| 训练拟合 BKT | 0.62100 | 0.58570 |
| 正则化历史逻辑回归 | **0.59662** | **0.55243** |

两个语料均在验证集选择了历史逻辑回归，然后计算测试结果。该模型只有全局截距、四个历史计数系数及技能截距，无用户固定参数，不需新增训练服务。不是原论文全部 LKT 模型的复现。

按用户成对重抽样 1,000 次，历史回归相对技能均值的用户宏平均损失差：CT 为 −0.01460，95% 百分位区间 [−0.02353, −0.00689]；AS 为 −0.07387，区间 [−0.08744, −0.06073]。此不确定性只针对当前留出用户和已选模型，不包含数据集选择、超参选择及跨领域迁移的不确定性。

必须保留的反例：

- **冷启动并非统一改善。** CT 每人首条响应，历史回归损失 0.68974，技能均值 0.57188；AS 首条分别为 0.66948 和 0.70598。不能从整体结果推出所有新用户都该用同一个预测器。
- **校准并非统一改善。** CT 的 ECE10 从技能均值 0.04565 变为历史回归 0.05100；AS 则从 0.01110 降到 0.00853。只看 AUC、平均损失或单一校准数都不足以支持能力概率展示。
- **未知技能证据不足。** CT 测试没有未知训练技能，AS 只有 6 条，不能据此声称跨技能泛化已验证。
- **跨语料迁移具有方向性。** 强制目标技能截距全部未知时，CT → AS 的历史回归损失 0.59022，AS → CT 为 0.62602；后者差于 CT 本域技能均值的 0.61202。公开参数没有无条件可迁移性。
- **负对照没有被隐瞒。** 打乱训练标签并重建全部历史特征后，历史回归测试损失 CT 为 0.66054、AS 为 0.65103，均失去原来的优势。它只排查部分标签/历史错误，不能证明所有泄漏已排除。

据此作出的工程判断：保留简洁历史预测器作为候选，后续模型门槛需要区分冷启动、已有历史和领域范围。**本轮没有把公开参数部署成组件掌握概率，也没有在已经看过的测试结果上挑一个新门槛并报告“独立成功”。**

## 2. 数值错误、协议和失败记录

首次运行暴露旧 BKT 网格函数的长序列浮点漂移：状态越界后产生溢出/NaN，旧函数仍会选择候选。这使第一次 AS 拟合 BKT 的结果无效。该产物和日志保留在 `.local-data/research/framework/prediction-invalid-numerics.*`，不作为比较依据。

修正措施为：观测/转移边界限制在浮点安全区间 `[10^-12,1−10^-12]`；非有限似然直接报错；结果 JSON 禁止 NaN。新增长序列数值测试，核对向量化网格与逐条预测的似然一致。之后按**相同数据划分、候选与超参**重跑，得到本文结果。由于首次结果曾被查看，这次是明确披露的数值修复重跑，不能称为第二份从未查看过的测试集。

原来小规模 CT 报告及其负面结论保留。新协议的用户分割不同，因此新旧 CT 数值不能直接作“算法改进前后”的对照。比较只能在本轮相同测试记录内进行。

AS 中多技能事件按 `(user, order_id)` 聚合后整体排除，未把同一响应复制到多个技能；最终保留的是明确的子样本。`correct=0` 含首次错误或求助，不能等同本地未求助检查。数据采集中的答对后停止机制也限制了学习速度推断，详见 `schema-audit.md`。

## 3. 真实生产算法的反例与修正

调用实际 `projectComponent`，生成仅有阅读机会、没有检查的确定性事件序列。

| 阅读日 | 旧指数 | 旧显示 | 新指数/显示 |
|---|---:|---|---|
| 0 | 0.20000 | 未接触 | 无表现观察，不展示能力数值／未接触 |
| 1 | 0.30025 | 阅读推进 | 无表现观察，不展示能力数值／已阅读 |
| 3 | 0.46463 | 估计熟悉 | 无表现观察，不展示能力数值／已阅读 |
| 30 | 0.98559 | 估计熟悉 | 无表现观察，不展示能力数值／已阅读 |
| 365 | 约 1.00000 | 估计熟悉 | 无表现观察，不展示能力数值／已阅读 |

修改后的内部实验先验保持 0.20，初值敏感性范围保持 0.10–0.35，均不因为纯阅读而收窄。它们未被当成准确能力显示；无独立检查时 `performance_observed=false`，前端只显示事实。修正前后的完整审计见 `passive-signal-audit.json`。

模型版本更新为 `kc-evidence-separated-v2`：

- 阅读自动累积覆盖并继续支持后续目标的准备条件，但不更新表现指数。
- 熟悉/困难自评改变下一步安排，不再施加贝叶斯似然比；“自评熟悉”单列，用户仍能减少重复阅读。
- 不同题族的首次未求助检查更新实验性表现预测。至少两个不同题族通过且最近检查通过时显示“检查支持”，该阈值是明确的证据摘要，未经统计能力认证。
- 最近失败、困难或真实回忆到期继续提示巩固；较新的独立检查替代旧自评的当前作用。旧自评仍留在事件历史，不改写原始事实。
- 星图图例、节点提示、右栏、详情和助手上下文使用一致语义；保留白绿风格、自动点亮、缩放和旋转。

该修复防止没有独立观测却越来越“确定”，不宣称解决了全部建模问题。独立题目仍为作者样本，实验性 BKT 指数仍未本地校准；旧页面回退模式仍有历史模型，需要在整体迁移时处理。

## 5. 复现

1. 取得 `evaluation-protocol.json` 中固定提交的两个 CSV，放到本地数据目录，不导入 WeKnora。
2. Python 环境需要 NumPy：运行 `python -m unittest discover -s scripts -p 'test_learning*benchmark.py'`。
3. 运行 `python scripts/learning_framework_benchmark.py --ct <ct.csv> --as-data <as.csv> --output <结果.json>`；输出位置的父目录应存在。记录会包含协议、脚本、BKT 实现、数据和结构核对文件的 SHA256。
4. Go 按本项目 CGO 启动配置运行 `go test ./internal/application/service/learning -run '^TestComponentPassiveSignalsDoNotManufacturePerformance$' -count=1 -v` 可重现修正后的纯阅读反例检查。

完整数值见 `prediction-results.json`。公开预测指标仅验证算法候选，未测得本地学习时间、延迟保持或推荐策略的因果收益。
