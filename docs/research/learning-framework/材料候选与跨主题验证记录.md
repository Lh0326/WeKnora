# 第三轮：通用候选材料与跨主题闭环

2026-09-12。依据冻结的 [材料候选协议](材料候选与验证协议.md)。目标是摆脱十个手写报告目标的专用构建器，同时保留来源质量边界；本轮没有把模型生成结果直接发布到用户知识库。

## 1. 已实现的通用流程

`kc-source-draft-v1` 接收明确选择的完整 Wiki 页面，通过已有聊天模型生成带目标、条件、解释、例子和引文的候选。每次 1–6 页、每页不超过 8,000 字符、合计不超过 24,000 字符、最多 8 个候选。超限不截断正文。输出来源哈希与逐项拒绝原因；生成结束再读取来源，变化后不交付过期候选。

这个过程不读取个人记忆或学习事件，不写共享材料或个人状态。模型不能自行把草稿标为可用，附带题目会被移除，先修建议降为相关候选。导入要求显式的 `ready` 状态及来源复核说明；这是可审计的整理流程，不是机械规则能证明语义正确。原有明确作者整理的旧包保持兼容。

来源核对后的学习单元现在允许 **0–3 道题**。无题目标仍支持阅读、熟悉/困难反馈和真实回忆；读过后不会因为没题就反复推荐阅读，也不会创造检查或能力数值。题目可在确有判断价值时另行整理，无需把全部知识改成题库。

复用已有 Go 模型调用、Wiki 仓储和 JSON 材料定义，无新数据库表、训练服务或运行依赖。新增数据只用于源材料与候选定义；个人事实继续使用原来的事件链。

## 2. 模型与环境记录

本知识库默认 Wiki 与摘要模型均为 `qwen3.8-max`，调用返回 403 `AllocationQuota.FreeTierOnly`，未产生候选。先尝试的四组默认调用及一次摘要模型调用属于额度失败，不计为材料质量失败或零候选的有效拒判。

核对已有设置后，复用了知识助手正在使用、已真实回答问题的 `glm-5.3`（本地模型 ID `4f0e5d9c-5a44-47a8-834c-ce4170f8be40`）。选它的依据是现有可用性，不是查看多模型质量后挑最好结果。没有修改知识库默认模型、凭证或计费设置。所有有效案例均保留该模型的首次完整候选，未按表现重新抽取。

一次调用前的本地数据库连接失败发生在工具长时间未返回期间，没有拿到模型输出；确认原进程结束、按启动说明检查基础服务就绪后重试。另有一次工具缺少运行库路径导致命令无法启动，已按项目 CGO 环境补齐。失败状态分别保留，没有算进有效生成数。

模型输出与当时程序/协议/输入摘要存于 [material-drafts-glm](material-drafts-glm/input-hashes.json)。之后只增加了两项运行边界：本地连接超时 5 秒、服务 120 秒超时覆盖材料读取至结果复查；提示词、候选筛选与这批模型输出未改写。冻结摘要用于复查当时版本，不冒充当前文件摘要。

## 3. 四组实际生成结果

全部来源是自编合成材料，覆盖并发、统计和工作流程；不是独立企业语料样本。

| 场景 | 候选数 | 观察到的能力 | 仍存在的问题 |
|---|---:|---|---|
| 同一个“锁”，同进程与跨机器不同用途 | 3 | 分开建立目标并保留作用范围 | 一处病句；一处把案例约定扩大成反向否定 |
| 两篇来源表达同一加权平均规则 | 4 | 核心目标合并且引用两来源；算例 66、70 正确 | 将一般条件说成必然结论；原始来源本身遗漏相等均值特例 |
| 常规发布与紧急修复的条件冲突 | 4 | 两类流程分别保留，没有抹平批准顺序差异 | 流程选择目标需更明确地限定在来源覆盖的情形 |
| 没有规则、条件或例子的待办材料 | 0 | 返回信息不足，没有编造处理流程 | 输入有显式不足线索，不能当作盲测拒判能力 |

11 个候选的引文与结构均通过机械校验。作者逐项对照后发现 **至少 5/11 需要修订**，其余 6 个只是“本次作者核对未发现问题”，不能称为语义准确率。没有独立评审者或学习者，也没有测得学习时间、任务表现或延迟保持收益。

一个重要反例：原统计来源写成“仅知道两个均值、不知道人数，就不能确定合并均值”，漏掉了两个均值相等的情形。模型会忠实继承这种缺漏。所以既要核对生成内容是否来自来源，也要核对来源的条件是否足够；逐字引用不能保证知识本身正确。原始来源和输出保持不变，修订另存。

## 4. 修订后的算法闭环

[作者复核记录](material-author-review.json) 保留每项判定、原句、修订句及原因。修订来源为 [material-boundary-sources-reviewed.json](material-boundary-sources-reviewed.json)，整理后的 11 个单元为 [material-boundary-reviewed-pack.json](material-boundary-reviewed-pack.json)。复核者是本原型作者 Codex，未冒称真实用户或独立人工审校。

生产代码的跨主题检查 `TestReviewedCrossTopicMaterialsUseProductionAlgorithms` 验证：

- 三类主题共 11 个单元用同一个导入器通过，不依赖初版课题报告中的十个固定键。
- 所有单元不含测验、不含模型硬先修，预算规划仍返回有效阅读步骤。
- 全部阅读后保留“已阅读”，独立表现观察为零；不会陷入没题就反复阅读的循环。
- 修订来源与旧来源版本确实有差别；使用旧来源导入修订包会被拒绝。

这证明结构与闭环可跨这些主题运行，**不证明全库自动制课、自动语义去重或学习收益已经实现**。本批合成材料没有导入 `weknoraq4`，用户仍看到其现有十个报告目标。未用工程生成操作制造个人学习证据。

## 5. 复现与使用

仍按项目启动说明使用 5173 前端、18081 后端及 Docker Desktop 开发基础服务。

共享材料候选入口：`POST /api/v1/learning/kb/:kb_id/components/draft`，需要知识库写权限。请求包含 `slugs` 和 `limit`；默认使用库的 Wiki/摘要模型，也可明确选择已有同租户模型 `model_id`。模型 ID 经过已有模型服务的租户作用域解析，不能通过请求注入服务地址或凭证。返回 `candidates`、`rejected`、来源哈希及待核对状态；它不是导入操作。

本地命令同样复用生产服务：

```text
go run ./cmd/learning-component-import -kb <本地知识库ID> -draft-slugs <slug1,slug2> -draft-limit 4 -draft-output <候选.json>
```

用 `-draft-model <已有同租户模型ID>` 仅改变这次生成调用。可选 `-draft-sources <来源数组.json>` 只供离线评估，不会把这些材料写入知识库。输出包含模型、生成时刻与来源版本。

内容核对后，将选定的 `material` 放入 `components` 数组，标记 `material_status: ready`，记录 `review_note` 和实际整理说明，再使用原有 `-file <材料包.json>` 或 `/components/import` 导入。导入前会再次检查真实知识库来源与哈希。不要将合成案例引用当作真实知识库来源导入。

## 6. 验证范围

最终 Go 回归覆盖学习服务、估计器、仓储、handler、router、类型和导入/候选命令。新增检查覆盖无题学习、模型自批与硬先修无效、越界/不存在/变化的来源、格式错误、模型选择范围、重复目标、来源版本，以及三类主题的完整算法链。前端 481 项测试、类型检查与构建通过，保留既有大资源包提示。

原型已经有通用候选入口与发布前的来源核对边界；当前自动质量筛选仍是机械检查，语义复核需要内容整理者参与。后续要减少复核工作量，应先建立独立来源审查样本与错误类型统计，不能用生成模型的高自信分数取代这一环节。
