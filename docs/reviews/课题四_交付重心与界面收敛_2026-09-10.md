# 课题四：交付重心与界面收敛

## 2026-09-11 最新定位：以建模与原型算法为中心

用户明确：重点考察四个切入点是否设计合理，友好交互服务于验证设计和获得有含义的学习动作数据。此前围绕完整目标验证、题库审核和生产成熟度的要求应收敛。以下定位适用于后续工作；本文后半部分的 9 月 10 日实现记录保留为历史，不要求继续扩建其中所有流程。

### 最小模型与四个问题

将用户在知识点上的原型状态记为 `x(u,k,t)=(接触证据, 主动选择, 可选检查证据, 可选复习安排, 内容版本)`。现有五状态是这些信息的规则投影；状态更新 `x(t+1)=F(x(t),动作,内容版本)` 必须可解释、可重放。这是当前实现的建模描述，不额外建立一套数据表，也不把状态标签当作已校准的真实理解概率。

| 切入点 | 原型要回答的问题 | 最小检验 |
|---|---|---|
| 关联 | 一次引用、问题或兴趣信号应该落到哪些知识点？直接触达与弱语义关联的边界是什么？ | 小知识切片中检查精确引用、仅文档引用、歧义和无匹配；比较关联粒度及误扩散。弱兴趣可影响排序，不直接认定学会。 |
| 度量 | 阅读、主动确认、疑问和回忆反馈如何改变状态？信号矛盾时如何处理？ | 固定行为序列验证更新、撤回、重复动作、内容变化与时间影响；少量独立检查可辅助发现自认偏差，无需全库先建题。 |
| 引导 | 给定个人状态、知识关系、范围与时间预算，为什么现在推荐这个动作？ | 同一情境比较目录顺序、仅个人状态、加入关联的推荐；检查约束、已会跳过、失败回看与完成后重排，报告规则的贡献及失效情境。 |
| 呈现 | 用户是否理解当前状态和建议，并能准确表达“已会、需再学、暂时换一个”？ | 用少量操作任务检查含义理解、误点、撤回、完成耗时及保存反馈；图色、统计与推荐一致。界面复杂度必须有助于理解或数据质量。 |

这些检查分别支撑规则正确性、局部设计合理性与可用性；真实学习收益须有相应数据后再作结论。合成动作可以检查更新逻辑，不能单独证明学习有效。

### 交互与数据的关系

默认路径：看到知识分布与当前建议 → 阅读或询问 → 确认已会／需要再学／换一个 → 状态与推荐更新。复习和练习按需要进入。

- 停留时长表示接触机会，“5 秒”是当前采集参数，不是理解阈值；离开页面不能直接判定不会。
- “已会”是用户自报，“需要再学”表示需要关注，“换一个”只排除本轮，不直接产生负向能力证据。
- 保留便捷确认、撤回和清晰的保存结果，避免用户因操作成本或不确定而反复点击。
- 评价交互时记录用户看见的建议及其后的动作，解释推荐曝光带来的选择偏差；更多点击、更多事件和只预测下一次点击均不能独立证明学得更好。

### 范围控制

当前保留知识图、五状态及证据区分、短路径、动作反馈、可用助手与基本画像权利。已有间隔复习、验证目标、题族和结构化任务作为可选能力，默认学习不依赖它们齐备。后续只在检验明确假设时选取少量代表性内容，不铺设全库题库和完整教学管理体系。

优先交付简明模型、规则或公式、参数含义、适用假设、反例、可运行演示以及小规模对照记录。无需新增基础设施、复杂算法名称、专门运营后台或生产验收流程来增加课题分量。已有必要的隔离与一致性修复保留；本次范围校正没有删除功能或修改用户数据。

## 9 月 10 日设计及实现记录

本文件依据 `F:\大厂计划！\Weknora\WeKnoraq4.docx` 的课题说明和本次用户要求编写。文档内容作为需求资料读取，不作为额外操作授权。此次目标是可解释、可复现、可验收的知识学习原型，同时保留必要的数据可视化和友好交互。

## 1. 交付定位

官方将“关联、度量、引导、呈现”列为可切入角度，明确不要求原型覆盖所有角度，也允许离线评估、小规模试用或对照实验任选一种验证方式。本项目选择四者形成一个小闭环，但不以功能数量衡量完成度。

核心论点是：在动作数据稀少时，以可追溯的知识关联建立探索范围，以有明确条件的验证证据表示学习状态，再用先修约束和学习目标安排下一步。系统不声称已经估计出每个人真实、连续的掌握概率。

演示闭环：打开知识库 → 看到目标验证进度和当前建议 → 阅读材料 → 完成独立检查 → 状态及网络同步更新 → 查看依据。前台只服务于这条闭环；研究指标、版本细节和对照结果放在验收材料中。

## 2. 四个切入点的实现与边界

| 切入点 | 最小实现及当前入口 | 可靠性约束 | 不能据此宣称 |
|---|---|---|---|
| 关联 | Wiki 页面作为导航节点；页面内定义可观察行为目标。引用通过 `ChunkRefs` / `SourceRefs` 映射到页面；历史文档亲和和记忆主题映射保留为弱关联。见 `collect.go`、`backfill.go`、`topicmap.go` | 精确分块引用优先，已有精确引用时不再对同文档所有页面泛化；记忆主题候选受限。LLM 可辅助主题映射，但模型输出的 confidence 不是经校准的正确率，更不能生成“已验证” | 访问过文档、助手读过页面或提到某主题，就已理解该知识 |
| 度量 | `objective_state.go` 按当前内容版本、合格作答及题族独立性计算未验证、部分证据、已验证、冲突、内容变化待复核 | 评分使用确定性答案键/关键检查；草稿、重复反馈、帮助条件不符、旧版本不能凑成当前验证。阅读、自述和机器访问与验证分开 | 已验证就是未来答对概率，或一次选择任务通过就具备实际部署能力 |
| 引导 | `path_plan.go` / `path_service.go` 使用目标、先修、已有接触、失败证据、可用题族和预算生成短路径 | 先修约束优先；计划不超预算；没有合格题目就明确降级；阅读后再检查，失败后可回到材料；相同输入可复现 | 文档次序天然等于难度次序，或推荐出来的路径已经证明提高学习效率 |
| 呈现 | 图、进度和证据抽屉共用目标状态。`objectivePresentation.ts` 只投影服务端结果；`ObjectiveWorkspace.vue` 呈现当前行动 | 活动分数、自评和跳过不能点亮“已验证”页面；一页多个已发布目标必须全部通过才显示深绿；错误状态不能伪装为无数据 | 页面已定义目标全通过，等于整页全部知识或整个人的能力都已掌握 |

“已验证”始终限定为指定内容版本、指定作答条件、指定检查规则下取得的证据。目标设计与题族独立性仍需内容审核；这部分不能由界面或单元测试代替。

## 3. 界面的收敛原则与本次修改

首屏保留三层信息：

1. **进度**：已验证目标数、单条验证覆盖进度条，必要时显示本次范围和需复核提醒。进度条分母是全库当前已审核目标，不是“真实掌握概率”，也不是所有尚未建模的知识。
2. **下一步**：一个主要按钮、一句推荐依据；多步计划显示小型步骤条，当前步骤突出，点击可浏览对应材料。只显示服务器实际生成的步骤，不补造“阅读—练习—验证”来装饰页面。
3. **按需查看**：完整路径与完成条件、验证依据、学习范围。学习记录和画像管理保留在底部；查看、导出、删除及停采仍可访问。

移除右栏旧活动统计、四档活动评分、待巩固清单、分组进度和旧模块推荐整块模板。它们不再与目标验证进度并列竞争。学习深度、时长、目标选择和直接验证移入范围抽屉；取消调整会恢复此前选择。取消每个步骤旁的多组操作按钮及重复导出/删除入口，不增加新的管理面板。

友好交互保留：阅读后返回继续的提示、进度条平滑更新且尊重减少动态效果设置、新增验证目标反馈、完成状态、任务加载及原位错误信息、答案保留和明确返回入口。提交结果不明确时提示先检查进度，不擅自宣称结果没有保存。

星图继续承担知识结构展示，但改用与右栏相同的验证状态：深绿表示页面已发布目标全部通过，浅绿表示部分证据，灰色表示未验证，黄色表示冲突或内容变化。悬停提供目标数量文字；图上的分母是页面数，右栏分母是目标数，两者明确标注。图上下一步标记使用当前短路径，不再使用旧活动推荐。无验证状态时显示不可用，不显示虚假的掌握百分比。

本次保留既有知识网络布局、底部画像权利入口和管理员健康视图，没有扩展成新的学习产品。旧活动计算接口仍服务于历史记录等现有用途；它们不是本次能力验证或效果结论的依据。

## 4. 以离线评估为主的验收方式

不把真人对照实验设为硬性前置。离线评估可以支撑“关联和路径在指定标注集上有效”，但要使用独立的参考答案，不能只把代码输出重新写成期望结果。

### 4.1 固定知识范围与标注集

先选一个可控、确有来源的知识库切片，覆盖概念和一类可确定性检查的应用任务。冻结节点、目标、来源、先修边、题族及内容版本。规模以能认真审核为准，不为了数量铺大题库。

关联样本至少含精确引用、仅文档级引用、同名歧义、无对应节点四类。每条记录保留输入记忆/引用、允许匹配页面集合、匹配粒度、来源和审核记录。路径样本覆盖零数据、已有基础、失败后补学、内容变化、题库耗尽、先修缺失/循环及小预算；参考标注应是“允许的下一步集合与约束”，而非强行规定唯一顺序。

开发样本用于修订规则；正式样本在规则冻结后运行。按文档/主题或情境分组隔离，防止同一道题换词后分别进入开发集和测试集。AI 可起草候选标注，未经内容审核的候选不能称作独立金标准。

### 4.2 分别回答四类问题

| 评估对象 | 指标及分母 | 对照与解释 |
|---|---|---|
| 关联准确性 | 精确率 = 正确关联对 / 输出关联对；召回率 = 正确关联对 / 标注关联对；无匹配误报率 = 应拒绝却输出关联的样本 / 应拒绝样本 | 比较仅文档匹配、分块优先匹配、主题候选映射；按匹配粒度分开。不能混用 LLM 自报 confidence 代替正确率 |
| 度量约束正确性 | 草稿误验证、重复题族误验证、跨版本凑证据、帮助污染等违规案例数 / 对应案例总数 | 对这些禁止性约束要求 0 违规；这是工程门槛，不是效果提升 |
| 度量外部有效性 | 冻结状态后的独立挑战失败率、未验证通过率，以及完整目标覆盖 | 复用 `docs/evaluation/objective-learning/` 中独立评估链。真实历史作答也可离线回放，但必须有时序、版本和未泄漏题族；没有相应数据则本项待评估 |
| 引导质量 | 下一步可接受率 = 落入独立标注允许集合的情境 / 可评估情境；先修违规、预算违规、无题却推荐验证的比例 | 同样目标、材料、时间预算下比较目录顺序与本项目。先修/预算/题库约束违规要求 0；可接受率比较回答局部推荐合理性 |
| 呈现正确性 | 服务端状态与文字、图色、进度口径的一致性；关键任务完成/阻断情况 | 错误不得呈现成“0 个目标”；阅读不得变成验证；改变范围不得提高全库覆盖。少量实际试用可补充是否看得懂，不作为唯一指标 |

0 分母统一记录“不适用/无样本”，不能写成 0% 或 100%。比较质量指标时同时报告各类样本数量、失败案例及分组差异，不只给一个总平均。若使用相关样本的区间估计，按文档/主题/参与者等实际独立单位分组，而不是把相关条目当成独立样本。

“先修约束引导优于目录顺序”可以先通过独立情境集验证；“让真实用户单位时间学会更多”则需要真实学习结果，不能从情境可接受率直接推导。两种结论的力度不同。原有 `simulate` / `walk`、工程夹具和点击预测指标也不能单独证明学习效率。

### 4.3 最小交付包

- 一份设计说明：节点与目标、信号分类、规则、路径决策及失败边界。
- 一个可运行闭环：关联 → 阅读 → 验证 → 更新 → 再推荐；以及画像查看、导出、删除。
- 一套冻结的独立离线标注集、基线、执行记录和结果；尚未审核的内容明确标草稿。
- 一张结果表：工程约束、关联质量、路径质量、外部验证、呈现检查分别列出；缺哪类数据就如实标待执行。
- 一段短演示：展示状态为什么变化及推荐为什么变化。界面不承载整份验收报告。

## 5. 本轮检查与未完成证据

本轮未修改后端评分和规划算法，重新运行 learning service、repository、learning-bench 包测试通过。新增图示投影测试覆盖弱信号不认证、同页多目标、草稿与无目标、冲突及内容变化、状态缺失；相关图布局测试通过。

前端类型检查、构建和完整测试的最终结果见同目录下的本轮验证记录。浏览器使用实际组件与模拟 API 检查 340px 右栏、阅读到验证、操作任务、范围调整、完成后证据入口和图/进度同步。模拟数据仅用于工程检查，不是效果数据。

仍需独立内容标注和相应效果数据，才能声称关联/引导在真实资料上达到某种准确率或改善学习效率。本轮没有假造审核签字或真人试用结果，也没有执行日常数据库迁移与后端重启。此次改动解决展示过载与口径混乱，不能仅凭界面改善认定课题效果已被证明。
