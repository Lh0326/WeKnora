## 事务和运行约束

- 锁粒度为主体，在其涉及的不同知识库/租户之间保持同一个删除与停采边界。PostgreSQL 使用控制行锁；SQLite 使用写事务保留锁。所有新增个人写入必须放在 `WithSubject` 中，并使用回调提供的上下文访问仓库。底层仓库 CRUD 并非自动开启主体事务的独立业务入口。
- 代际在删除和设置变更时递增。旧操作必须使用开始时捕获的代际，不能在写回之前刷新代际来绕过删除。`optOut=false` 时删除完成后新发起的操作可以正常建立新的记录。
- 映射的模型调用在事务外，提交阶段再检查代际。重放在主体锁内读取及提交，避免覆盖并发写入。主体历史过大时会阻塞同一人的写入，应观察耗时和锁等待。
- 回放分页消除了旧的 10,000 条硬截断，但当前仍把作用域历史保留在内存，后台重放单轮默认 30 秒超时。超时事务回滚，不等于支持任意规模历史；流式检查点和超大历史压测仍是容量扩展工作。
- 历史回填采取保守策略：发生过删除或设置变更、代际大于零的主体不重新导入旧记忆，避免从其他子系统恢复已删除的学习画像。它不会禁止该主体之后的新学习操作。
- `replay_hash` 是指定投影版本下有序事件输入的审计摘要，不是防篡改签名或学习效果认证。在线写入后摘要为空表示需要重新做完整核验，不能继续展示旧摘要为当前证明。

## 内容版本与迁移

PostgreSQL 本工作区新增迁移为 `000089` 至 `000091`；SQLite 对应 `000016` 至 `000018`。以部署环境当前迁移版本为准，由项目正常迁移机制顺序执行。新增字段包括主体控制代际、题目 `evidence_hash`、事件与作答的 `original_slug`、投影版本和摘要。

本轮未对任何运行中的业务数据库应用迁移。迁移和新增 Go 文件必须一起纳入提交。已有早期修复版本如已在其他环境执行过同编号但不同内容的迁移，需要先比对迁移文件与实际 schema，不能把改过的旧编号当成会再次自动执行的新迁移；应另发递增版本的补充迁移。

题目摘要使用 `quiz-evidence-v2` 域标识，包含页面标题、类型、slug、正文和截断证据集内按 ID 排序的材料内容。旧摘要/空摘要不自动冒充新版本；上线后旧题会暂停服务，维护按新证据补齐。临时读取失败时暂停不确定题目的出题或计分；确认缺失时维护将其失效。检查提供的是服务时点的有效性，不会撤销材料变更前已经正常完成的历史作答。

每次最多使用前 20 条引用材料作为生成依据；缺少其中任何有效材料时不以残缺快照出题。发布前版本校验不能证明模型输出语义必然正确，人工审题仍需完成。

`original_slug` 保存从本版起迁移时的原始名称。已被旧版本覆盖、且没有原始记录或备份的历史名称不能凭代码恢复；旧导出的历史名称完整性必须单独说明。

## 回放输入与协议

入口：

```powershell
go run ./cmd/learning-bench -mode replay -export <本地导出JSON路径> -topk 5,10
```

两种顶层格式均可：`{"events":[...],"quiz_attempts":[...]}`，或 `{"data":{"events":[...],"quiz_attempts":[...]}}`。`edges` 作为兼容字段可被读取，但当前图不作为过去的图使用。

事件要求：非空 `id`、`tenant_id`、`subject_id`、`knowledge_base_id`、`slug`、`occurred_at`；学习权重使用事件中冻结的 `weight`。`created_at` 可用时还要求在预测时点前已到达。缺失到达时间的旧记录只能按发生时间近似，不能宣称已证明不存在晚到泄漏。

可选 `recommendation_snapshots` 是经采集者确认在 `at` 时已经存在的生产元数据。示例结构：

```json
{
  "events": [],
  "quiz_attempts": [],
  "recommendation_snapshots": [{
    "tenant_id": 1,
    "subject_id": "web_user:example",
    "knowledge_base_id": "example-kb",
    "at": "2026-09-01T08:00:00Z",
    "input": {
      "Pages": [{"slug":"concept/example","page_type":"concept","title":"Example"}],
      "Edges": [],
      "HasQuiz": {"concept/example": true},
      "Affinity": {},
      "DocOrder": {"concept/example": 0},
      "Material": {},
      "Skips": {}
    }
  }]
}
```

以上是形状示例，空 `events` 不能执行评测。`input` 直接使用生产 `recommendInput` 的导出别名；字段名采用示例中的 Go 字段名。完整历史输入应包含页面/别名、可用题资格、先修边、材料顺序、材料上下文、跳过设置和熟悉材料映射。状态、直接作答证据、最近行为和自评由时点前历史重建，不信任快照中预计算的用户状态。

- 快照必须属于同一完整作用域，且 `at` 严格早于预测时间。工具不会把今日图结构变成历史快照；本轮也没有伪造真实用户的历史快照或自动部署新的快照采集服务。
- 有历史快照时，证据、作答和真值按该时点已知别名统一节点身份；不能用未来别名把过去命中率抬高。
- 无快照时，仅人类此前触达的节点进入候选集，题目资格在首次测验之后才可见。这是“已观察节点代理评测”，不是完整生产策略回放。真实系统可从页面目录推荐首次接触的节点，因此不能把代理模式的首触必失解读为生产系统必然失败。
- 同一时间戳事件作为一批，先预测整个批次，再消费它们作为后续输入。切分不拆开同批；静态约 80/20 切分只输出一份冻结列表。随机、热度、生产推荐器使用同池且不共享随机数消耗。
- 真值只纳入人类事件。不可达真值计入分母并单列；作用域分别报告，在线结果同时给出微平均与宏平均。零有效测试样本不能报告为通过。
- 当前命令为单种子描述性验证。命中率/MRR 衡量下一次行为预测，不直接证明掌握提升。调参应使用训练/验证主体，最终测试主体独立保留；不能见到测试分数后持续调权再把同一分数当验证结果。
