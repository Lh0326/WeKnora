# 课题四：学习引导与掌握闭环优化

## 需求依据与交付目的

已完整提取并阅读用户提供的两份 Word 文档：`WeKnoraq4.docx` 和 `WeKnora 开源实战课题.docx`，所在目录为 `F:\大厂计划！\Weknora`。两份文档的课题四要求一致：连接用户记忆与知识网络，形成度量、引导、呈现的闭环，给出设计、可运行原型和验证方式，同时支持个人数据查看、导出、删除及隔离。

本轮重点是企业知识库的快速学习：先知道哪里不会，再得到可执行的学习顺序，学习后立即得到可靠反馈。对比 9 月 9 日提交中的分类、待巩固和分组能力，本轮恢复可交互的数据分类，同时让每个分类、模块、推荐直接通向阅读与状态更新。

## 一、度量：全部知识点都可管理

知识点身份沿用 Wiki 的 entity/concept 页面 slug，分组沿用真实 Wiki 文件夹。没有题库的知识点也进入分母，不再因为没有审核目标而全部显示“未验证”且无操作出口。

| 状态 | 来源与含义 | 呈现与下一步 |
|---|---|---|
| 未开始 | 无有效个人接触记录 | 灰色，推荐建立基础 |
| 学习中 | 实际阅读、主动标记已读或问答引用接触 | 蓝色，可回看或确认理解；仅有引用不会宣称“已读完” |
| 自认已会 | 用户主动确认当前内容已理解 | 浅绿，移出默认待学；不会增加客观验证数 |
| 验证通过 | 当前版本的已审核目标满足确定性证据契约 | 深绿，显示验证依据 |
| 待巩固 | 主动要求再学，或内容变化/验证冲突等需复核 | 琥珀色，优先处理 |

概览的掌握覆盖是“自认已会 + 验证通过”的知识点比例，两类数量单独显示；它不是个体答对概率。星图、分类清单、模块统计与助手读取相同节点投影。严格目标的部分证据、冲突和版本失效仍可在验证依据中查看。

阅读计时只计算可见停留：5 秒记录普通阅读，60 秒在离开页面前反馈深入阅读；快速切页不计，后台隐藏不计。后端保留去重和事务规则，重复停留不能反复堆高验证证据。已知的简单内容可以立即点击“我已学会，点亮”，无需等待计时或先做题。

主动状态与不可变事件一同保存，绑定用户、租户、知识库和内容版本。重复确认幂等；“需要再学”撤回已会选择，重新阅读后可主动标记已读或重新确认。旧版本确认不能自动覆盖内容更新提示。机器代读和弱主题关联不能代替人的学习事实。

## 二、引导：有约束、可解释、可退出的短路径

当前策略版本为 `path-plan-v4`，使用确定性状态机、先修遍历和时间预算约束。同一输入产生相同计划，可回放检查。

1. 按所选模块、目标和深度缩小范围，排除当前已会和本轮临时跳过的节点。
2. 为主动要求再学的内容保留优先位置；已验证目标的到期复核至多占一个位置，避免新目标过多挤掉复核。
3. 审核目标沿人工先修关系遍历；缺前置材料时安排桥接阅读。推断关系不作为严格门槛，环、缺失、题库不可用有明确降级反馈。
4. 普通知识点优先当前待巩固、最近接触点、最近模块，再按来源材料位置排序。内容长度估计阅读时间；已经接触的内容安排“确认理解”，用户可以继续阅读、直接确认或换一个。
5. 最多返回五步，估计总时长不超过预算。阅读、确认、验证均显示原因、预计时间和完成条件；操作成功后重算，已会节点让位给后续内容。

5/15/30 分钟是快速预算，可在设置中调整至 1–120 分钟。“换一个”仅影响本轮，不制造掌握记录；可恢复全部临时跳过内容。点击模块后滚动定位到新的当前步骤，避免用户看不到筛选效果。范围偏好目前保留于页面会话，尚未实现跨设备同步。

将三处二次复杂度排序替换为标准排序，并复用已经读取的行为事件，减少全量重复查询。万级节点基准只验证纯路径计算与近期锚点计算；不能将其等同于生产数据库端到端容量。

## 三、呈现：从分布看到下一步

右栏由掌握分布环、五状态清单、预算选择、当前行动、后续步骤、模块覆盖条组成。分类可以搜索知识点，列表分批展示；模块按待巩固和待学数量排序，悬停联动星图。

1440 像素宽度保留星图和右栏双列。900 像素宽度默认显示导航，通过“学习导航 / 知识星图”同页切换，避免整屏图形把当前行动挤到首屏之外。

点击星图或路径打开页内阅读抽屉，保留学习场景。抽屉提供摘要、正文、关联跳转、明确的返回入口、状态控制和继续下一项；长文滚动时状态操作保持可见，也可转到完整 Wiki。内容沿用 Markdown 清洗与受保护文件访问机制。

加载失败显示错误与重试，不伪造零进度；自动保存提供进行中、成功、失败及关闭采集四类反馈。关闭采集后，服务端返回 `recorded:false`，页面不再声称自动保存成功；用户仍可明确操作自己的学习状态。

## 四、知识助手修复

真实浏览器定位到聊天组件普通 JavaScript 中误用了 `ref<any>(null)`，导致运行时 `ReferenceError: any is not defined`，助手显示外框却没有可用输入。现已修复并增加语法回归检查。

上下文改为实例内、按用户/租户/知识库隔离的响应式缓存，切换范围或强制刷新后拒绝旧响应覆盖。学习状态变化会刷新助手上下文；当前节点包含正文摘录与实际状态，无法读取的数据明确标为不可用。

同时修复初次历史加载与发送消息竞态造成的重复问题，隐藏用户气泡中的宿主上下文协议字段；图片预览只在实际打开图片时挂载，消除普通消息下多余的“图片无法显示”。

追加联调发现未完成的 RAG 历史流被 `markRaw` 处理，后续回答缺少响应式更新，出现服务端已有答案、页面仅有检索状态的情况。现仅对已完成历史应用该优化，恢复中的回答保持响应式；新增续传、新回答和历史竞态三个真实 composable 回归。助手上下文也明确区分历史操作与当前状态，避免把用户撤销已会误解为保存失败。

## 五、验收记录

真实联调使用用户登录后的 `weknoraq4` 知识库，已有 18 个知识点、11 个模块：

- 知识助手实际回答了知识点总量、已会/验证数量和下一步内容，完成检索与流式回复。
- WeKnora 节点“确认已会”后，自认已会增至 1、待学减至 17，星图同步变绿，下一步让位给五层架构；刷新后保留。
- “需要再学”后，节点变为待巩固，并进入路径首项，模块排序同步变化。
- 测试结束将该节点恢复为学习中；确认测试没有被留下当作用户实际掌握结论。真实阅读与这些显式测试事件仍在历史中。
- 在阅读抽屉内验证五层架构正文、关联链接跳转和可见停留反馈。
- 选择度量机制后，路径缩小到该模块的三个知识点。

前端全套 453 项测试通过；类型检查和生产构建通过。Go 的 learning service、repository、database、types 测试通过，handler 的 Learning 回归通过；session/router 包在该筛选下没有匹配用例，不算作业务断言覆盖。节点状态与路径测试覆盖无题库、版本变化、重复事件、错位用户、时间预算、先修依赖、临时排除及显式复习不被大型目标集合挤掉。

本机 i7-13700H / Windows amd64 的 10,000 节点纯算法基准：短路径平均 **8.62 ms/次**、约 **671 KB/次**分配；近期锚点平均 **10.36 ms/次**、约 **1.97 MB/次**分配。这是 `go test -bench TenThousandNodes -benchmem -benchtime=1s` 的本机结果，不含数据库、网络和浏览器绘制。

生产构建保留现有大分包及动态/静态混合导入提示。未以本轮相关包测试声称整个仓库后端全量通过：此前全量 handler 运行的本地 sandbox 可用性检查在当前环境失败，与学习功能断言分开记录。

## 验收补充与边界

本轮验证工程闭环和界面可用性。个性化时间估计、14 天到期复核规则和排序优先级尚未通过真实员工长期学习数据校准；没有宣称实现并验证完整 BKT/FSRS 个体模型，也没有将模拟行为命中率当作学习效果。企业推广仍应通过保留挑战、学习耗时和延迟保持测试评估，既有独立评估工具保留用于此目的。

启动与复现命令见根目录 `README_LEARNING.md`。当前工作区原有修改保留，未代替用户提交或覆盖历史提交。
