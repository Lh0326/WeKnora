# 课题四阶段5：独立评估链路 — 交付报告

日期：2026-09-10（凌晨续）。实施 03_评估执行与结果模板.md 的核心协议：冻结快照挑战评估 + 数据来源严格分离 + 用户级聚合 + 诚实 N/A。

## 1. 实际行为变化

新增 `cmd/learning-bench/assess.go`（纯评估器）+ `-mode assess` 命令行入口。**原有 simulate/replay/verify/walk/optimize 五模式零改动**——它们各自的用途（规则一致性/行为预测/校准）保持不变，不换标题叫"学习效果"。

**数据来源四标签**（03 §4.5）：`engineering_fixture` / `synthetic` / `expert_scenario` / `real_user`。每个参与者携带 `data_origin` 字段，输出按来源分开计数；**synthetic 永不冒充 real_user**（有专项测试钉住）。

**冻结快照协议**（03 §4.2）：`state_as_of ≤ presented_at < graded_at` 硬序——违反时整个评估被拒绝（未来标签检测）。题族重叠（训练证据中包含留出题族）被检测并报告为泄漏警告。

**阶段分离**：`train / practice / pretest / posttest / delayed` 五阶段常量；正式评估的留出题族不得出现在训练证据中。

**指标**（03 §5.1/5.2）：
- 已验证失败率 / 已验证成功率：`*float64`（nil = N/A，**绝不 0%**）
- 未知组通过率（unverified / unknown 分开）
- 系统验证覆盖率
- 主结果 = 用户级后测均值差（guided - baseline）
- 样本量：每用户 1 个计数（多次试次不重复计）

**缺失保留**：未完成后测的参与者保留在 origin_counts 中（不删除）；withdrawn / missing_post / missing_reason 字段如实记录。

**解释边界**（03 §8）：非 real_user 来源时打印"This is a demonstration of the protocol, not evidence of learning effectiveness. No real-user learning outcomes are claimed."

## 6. 使用方式

```bash
go run ./cmd/learning-bench -mode assess -assess-input=<path-to-json>
```

输入 JSON 格式见 `AssessInput` 类型；合成演示输入示例在 `assess_test.go` 的 `TestStage5_RunAssessEndToEnd` 中。

**正式模板**：无真人数据时运行任何输入，报告自动打印"N/A"与解释边界声明（03 §8 的"只有工程和离线场景结果时"句式）。

## 补充（第二轮）：分子分母 + Wilson CI + 调参守卫 + 持久化报告

- **分子分母暴露**：AssessMetrics 新增 verified_n/verified_passes、unverified_n/unverified_passes、unknown_n/unknown_passes、total_objectives/verified_objectives 字段——每个比例的原始分子分母可审计。
