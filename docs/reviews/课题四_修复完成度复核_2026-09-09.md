## 本次实际补修

### 1. 掌握度与测验的一致性

- 补充反例：logit 已在 -4、稳定性 1 天、闲置 180 天后答错，原补丁仍把概率从 **0.002735811 提升到 0.017986210**。现在负更新的下限不得高于更新前已衰减状态，错误不会因截断获得奖励。
- 零权重事件在 FoldEvent 入口直接返回原状态，避免离线路径将去重阅读/不确定答案变成新的计数和遗忘时间锚。
- 跨日复答的即时 NextReviewDays 原来仍用旧 facts，刷新画像之后才显示新门槛。现在即时反馈与画像读使用同一事实归约。
- 同题 48 小时内已提交过任何答案，包括“不确定”，再次提交只提供反馈并记录零权重轨迹，不继续累计能力分和稳定性；间隔外可重新取得独立证据。
- DirectFacts 读取完整作答历史，错误/不确定记录参与“答案已展示”的判定。不能只查正确记录，否则错后立即照答案纠正仍能解锁档位。
- 历史查询失败时不按“第一次作答”发放完整证据。停用的题目 ID 不再可通过直接接口提交。

涉及：[fold.go](F:/study/WeKnora/internal/application/service/learning/fold.go)、[gate.go](F:/study/WeKnora/internal/application/service/learning/gate.go)、[grade.go](F:/study/WeKnora/internal/application/service/learning/grade.go)、[read.go](F:/study/WeKnora/internal/application/service/learning/read.go)。四种界面语言的门槛说明同步更新。

兼容性：没有重写历史事件权重；旧重复练习已经积累的分数不会自动全部撤销。门槛由完整尝试历史重新计算，可能比旧版更保守。旧 QuizRepeatDecay 名称保留供旧配置兼容，不再控制线上计分，也不再作为本次拟合参数。

### 2. 校准计算和输出

- 旧 refoldWeight 将每个 slug 的第 N 次测验视为同题第 N 次重复，跨日或不同题也被折扣。同一测试轨迹下，校准损失为 **0.179174**，按实际冻结权重和生产更新器计算应为 **0.472310**。现改为保留历史行已经解析好的折扣，只缩放基础事件权重，不再猜测同题重复次数。
- 输入可携带 `base_weights`（事件类型到记录时基础权重的映射）。旧输入没有该元数据时，明确报告“假定当时使用当前随代码发布的基础权重”。若历史曾采用其他参数而没有元数据，不能据此声称准确恢复了历史模型。
- 没有任何历史事件的首次测验也计入评分；尝试按时间排序，作用域按 tenant/KB/subject/slug 隔离并确定遍历顺序。
- 排除已看答案后的即时重答标签；相同时间戳的一组作答不能拆到训练和验证两侧；没有时序训练样本时拒绝拟合。
- 原输出打印全样本损失，却附上验证集改善比例，而且 JSON 不含验证样本量。本次分别输出全样本和时间验证集损失、验证 N、改善依据及协议说明。
- 删除没有可靠重建语义的 QuizRepeatDecay/BackfillDiscount 拟合维度。已有测试只证明搜索动作、约束和验证判决，不能证明恢复了生成参数，故相关测试改用与断言一致的名称。

涉及：[optimize.go](F:/study/WeKnora/cmd/learning-bench/optimize.go)、[replay.go](F:/study/WeKnora/cmd/learning-bench/replay.go)。此处修复了 replay 复用的权重计算，但没有把整个推荐 replay 协议变成可信效果实验。

## 尚需完成的工作，按优先级

1. **删除/停采与事务边界。** 将个人写入、停止采集和删除串行化到数据库层，加入删除代际或等效机制；异步模型返回后检查代际，不能只检查当前开关。用故障注入和真正的删除调用测试失败回滚与在途返回。现有名为 NoResurrectionAfterDeleteAndOptOut 的测试只预置停采状态，没有真实驱动并发删除流程。
2. **题目内容版本及来源分离。** 题目绑定内容/证据版本，变更后停止出题和计分直到重审；Agent 自动读页与用户可见阅读仍共用 wiki_tool_read，不能把工具访问当作本人学习。正向浏览刷新同一个掌握状态的问题仍应通过分通道设计解决。
3. **有版本的确定重放。** 统一事件顺序和状态版本，处理晚到事件；后台从事件发现缺失投影，使用完整分页/游标。多来源 slug 合并及尝试随节点迁移仍需事务化，不能只搬掌握度行。
4. **可信评估与交付说明。** replay 仍缺历史节点全集、完整生产推荐输入和一致候选资格；未来节点/题目泄漏和静态当前时间等原问题仍在。现有时序校准可用于开发验证，不支持“学得更好”的结论，也不支持旧 35.94% 改善数字。需独立数据、人工题目检查和最小前后/延迟测验。

本次完成的是针对性复核和确认缺陷的补修。保留现有架构是合理选择，但在上述边界闭合前，应把成果定位为可运行、可解释的学习原型，不能标为所有审查项已解决或多实例生产可靠。
