# 内容修订与人工复核清单

本轮是代码与内容逻辑复核，不是内容所有者签字。`learning-seed` 仅导入草稿，不再从 `-reviewer` 字符串制造人工审批。已有自动盖章记录在 000095 / 000022 迁移中按原有精确说明文本退回草稿。普通真实人工审核记录不按此文本规则处理；缺少新来源哈希的旧目标仍保守展示为待审核。

## 对原演示包的修订

| 目标 | 原问题 | 已做的修订 | 发布前仍要核验 |
|---|---|---|---|
| LLM 初始化参数 | 目标说 model 与 temperature，第二题却考类名 | 第二题改为固定模型、改变温度的参数边界 | 引用页和片段是否支持新问题与解释 |
| 温度方向 | “高更随机”和“低更稳定”是镜像；低温不保证完全复现 | 两题归并同一题族，去掉保证可复现的暗示 | 必须补真正独立的第二题族，否则该目标最多 partial，不能宣称六个概念都已有两族 |
| LangChain 职责 | API 密钥来源与框架职责不对齐 | 替换为组件编排职责的场景判断 | 是否与第一题仅为同义改写；必要时合族 |
| 工具调用流程 | 宣称模型直接执行外部工具；第二题仅记忆 Agent 名称 | 改为模型提出请求、应用执行回传；补检查结果回传的情境 | 文档若把模型/应用责任写混，先修正文档再审核 |
| 函数工具识别 | 目标覆盖三种定义，题库只覆盖函数工具 | 收窄目标到 @tool 和描述信息 | 若要保留三种工具目标，补绑定和自定义类的真实任务 |
| SQLite 定位 | 内容贴近记忆，无法证明数据库操作能力 | 保留为概念目标，未包装成数据库操作能力 | 题族独立性和错误选项的合理性 |
| 知识库升级方案 | 题干已给出内存字典，答题只是抄答案 | 改为持久化、检索参与生成、来源关联三项约束选择；能力类型改 operation | 新约束可能超出原引用，必须补充分源；只能认证配置选择，不能认证部署/编码能力 |

所有改写保留为草稿。解析明确说明需要核验来源；不会把“参考页面”冒充“逐项已核实原文”。源引用目前是原包候选 ID，若迁移到另一知识库必须重新绑定，不能按字符串碰巧存在就接受。

## 内容负责人实际审核时要留下什么

每个目标至少记录：能观察到的行为、题目/任务为何能测该行为、当前来源及版本、允许的帮助条件、关键检查、合格判据、题族关系、审核人和理由。概念契约 v1 使用闭卷的两个独立题族；开卷应用采用结构化任务，不能把开闭卷证据混成同一概念认证。

审核单应逐项给出结论，而不是统一写“已审核”：

- 目标行为是否被题目真正覆盖，是否把记住名词过度解释为会操作。
- 来源是否支持正确答案，也能排除干扰项；材料错误时优先修正文档。
- 两个题族是否依赖不同的判断过程，是否只是正反问、换词或重排。
- 任务情境是否泄漏答案，是否存在多个合理方案却只接受一个。
- 技术约束是否在题干中足够明确，例如单机、持久化、允许的检索方式。
- 训练题与独立评估保留题是否隔离；不能用做过的题证明泛化掌握。
- `prereq_objective_id` 与人工 prerequisite 边是否确实必要。模型建议边不能直接成为门槛。

自动结构校验可以拒绝重复选项、空检查、无来源、过期版本和跨库绑定；不能替代这些语义判断。

## 当前可交付的准确说法

可以说：已实现草稿/审核/发布/试次版本冻结/来源失效/独立评估链路；提供了修订草稿和审核清单，系统不会因镜像题或重复反馈凭空增加独立覆盖。

不能说：七个目标都已完成人工内容认证；十二道题都代表十二个独立能力证据；配置选择任务证明用户能部署企业知识库；工程界面演示已经证实真人学习效率提升。

后续审核应先补内容，再做小规模试用。代码修复可以消除不可信认证，不能代替参与者和内容负责人实际完成研究。
